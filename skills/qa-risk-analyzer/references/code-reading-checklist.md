# 代码阅读检查清单

> 来源：qa-risk-analyzer → 深入读代码，做因果推理

用 Read 工具把 scope 内的核心实现文件全部读一遍——Controller、Service、Mapper XML、DTO/VO、前端页面组件和 service 层。

**关键词匹配不是风险分析。** 读代码时要带着以下问题逐文件审查：

## 1. 资金流转

钱在哪里流转？（余额扣减/充值/兑换/结算——每一步的 before/after 一致性）

- 扣款和入账是否在同一事务中？
- 金额计算精度是否统一（BigDecimal vs double）？
- 异常回滚后资金状态是否一致？

## 2. 状态机

状态机在哪里？（哪些字段在什么条件下从什么状态变到什么状态）

- 状态转换是否单向？（如 0→1 后能否回到 0？）
- 是否存在非法状态跳跃？
- 并发场景下状态是否被正确保护？

## 3. 并发窗口

并发窗口在哪？（分布式锁粒度对不对、事务边界在锁释放之前还是之后）

- SELECT FOR UPDATE 是否覆盖了所有并发敏感的读操作？
- 锁释放和事务提交的先后顺序是否正确？
- 是否存在 double-consume 窗口？

## 4. 权限边界

权限边界在哪？（哪些接口依赖 UserContext、哪些是公开接口白名单）

- 跨用户操作是否有归属校验？
- 敏感字段是否被脱敏？
- 公开接口是否有适当的限流/防护？

## 5. 异步链路

异步链路在哪？（消息队列、定时任务、SSE 事件——失败后会不会重试、会不会丢、幂不幂等）

- fire-and-forget 失败是否隔离保护？
- 事件消费是否幂等？
- 异步链路失败是否会影响主流程？

## 6. 异常路径

异常路径覆盖了吗？（余额不足、资产已用、参数非法、概率表缺失——每种异常有没有明确错误码）

- catch 块是否吞掉了异常但没做补偿？
- 辅助功能失败是否会拖垮主流程？
- 错误码是否对调用方可区分？
